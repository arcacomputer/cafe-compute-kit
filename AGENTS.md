# Cafe Compute Kit

Two app workspaces, one event per deployment. Read README.md, docs/architecture.md and app-local security/proof docs before edits. The public configuration is a whitelist projection, never a serialization of environment or private operations.

Use Node 22.22.2. Commands: npm ci; npm run check:source; npm run build; npm run test:unit. Native/browser proof needs explicit disposable PostgreSQL and Chromium prerequisites, documented in apps/feedback/PROOF.md. Never silently skip those gates or describe generated harnesses as executed proof.

Preserve separate runtime/admin/sender DB privileges, canonical HTTPS origin, host-only cookies, CSRF, atomic quota/receipt transactions, stable assignments and durable send fences. Access is not attendance or benefit eligibility. Consent/photos cannot gate code allocation. Photos default off; enabled uploads are private originals with disclosed metadata limitations.

Never commit private env files, secrets, cookies, actual rosters/code stock/photos, exports, generated TLS keys or operational audit logs. Never deploy, send, import, change gates or visit redemption URLs without operator authorization. In-process test bindings must not become public debug routes.

Keep both public languages, mobile behavior, keyboard controls, no-JS slides and print fallback working. Native proof is Linux/local-adapter evidence, not actual Cloudflare/Neon/R2/email/redemption verification. Keep fixes focused and record the exact checks actually executed.
