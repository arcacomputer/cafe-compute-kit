# Event content checklist

Use the event site as a public template, not a record of an event that has already happened. Do not use the private feedback database as a public content API.

## Before announcing

- [ ] Choose static-only or combined mode and a canonical HTTPS hostname. If static-only, hide/disable private feedback links.
- [ ] Copy the public event example into your own reviewed configuration. Label unresolved dates, venue, speakers and counters TBA; remove sample-only claims before announcing.
- [ ] Confirm event title, timezone, location/accessibility information, registration link, organizer/support contact, agenda and authorized sponsor wording in both locales.
- [ ] Use only assets you can publish. A software MIT license does not license a provider logo, font, video or attendee image.
- [ ] State benefit conditions only after confirmation; do not promise a value, eligibility or official endorsement from the sample copy.

## Resources and slides

- [ ] Replace placeholder onboarding links with reviewed official documentation and a safe example project. Do not put API keys in a browser slide, screenshot, repository or shared terminal history.
- [ ] Let attendees create and retain their own provider credentials; never collect them through the feedback form. Use synthetic output in demos and check costs before running live calls.
- [ ] Rehearse both `/slides/` and `/en/slides/`, resources routes, keyboard navigation, small screens and offline/failure expectations. Verify exact public links without visiting any private redemption URL.
- [ ] Keep a fallback copy of slides and accessible text resources. Registration/check-in remains in Luma or your chosen external system, not an invented backend here.

## After the event

- [ ] Export actual check-ins privately, then follow the [operator runbook](operators.md). Registration is not attendance, and login access is not benefit entitlement.
- [ ] Invite feedback only after separately approving sending. Honest criticism and N/A remain valid; optional photos and unchecked reuse consent are never benefit conditions.
- [ ] Write a recap using confirmed facts. Use no sample attendance totals, fabricated outcomes or AI-invented testimonials.
- [ ] Select material manually from private exports. Obtain rights/consent, inspect/redact derivatives and confirm quote context and attribution. No automatic dashboard-to-gallery publication.
- [ ] Preview English/Spanish homepage, resources, slides, recap/gallery and missing-route behavior before publishing only the intended static output.
- [ ] Set and execute retention/cleanup dates for originals, raw answers, exports and backups while preserving minimal assignment history.
